# AGENTS.md

TornTools is a browser extension for [Torn.com](https://www.torn.com), built with WXT, Svelte 5, TypeScript and
Tailwind CSS 4. A subset of its features is also published as standalone userscripts.

[CONTRIBUTING.md](CONTRIBUTING.md) is the human-facing contract and still applies. This file only covers what an agent
must actively do differently.

Detailed, area-specific conventions live in [.cursor/rules/](.cursor/rules) and attach automatically when you touch the
relevant files. Read the matching rule before writing code in a new area.

## Toolchain

Bun only. There is no `package-lock.json`, `yarn.lock` or `pnpm-lock.yaml`, and CI runs `bun install --frozen-lockfile`.
Never invoke `npm`, `yarn` or `pnpm`, and never generate a competing lockfile.

```bash
bun install --frozen-lockfile
bun run dev:chrome        # or dev:firefox — live-reloading dev build
bun run verify            # lint + types + svelte types + tests (matches the PR gates)
```

## Verifying your work

`bun run verify` is the single check to run before handing work back. It chains the four gates that CI enforces on every
pull request, so if it passes locally the PR checks should too.

Run them individually when you only need to re-check one:

| Command | Gate |
| --- | --- |
| `bun run lint` | Oxlint — CI uses `--max-warnings 0`, so warnings fail too |
| `bun run types` | `tsc --noEmit` |
| `bun run types:svelte` | `svelte-check` |
| `bun test` | Bun test runner |
| `bun run build` | Full Chrome + Firefox build (also a PR gate, but slow — run when you changed build config, entrypoints or the manifest) |

Formatting is not a PR gate; `code-quality-writing.yml` applies `oxfmt` on merge to `master`. Still run
`bun run check:fix` (`oxlint --fix && oxfmt`) so diffs stay clean.

## Repository map

| Path | Contents |
| --- | --- |
| `src/common/features/` | ~202 features, one folder each. Shared by the extension and the userscripts. |
| `src/common/pages/` | ~23 per-page setup modules that install listeners and fire custom events. |
| `src/common/utils/` | Storage, API, DOM and formatting helpers. Check here before writing a new utility. |
| `src/common/constants/` | Shared Torn constants. |
| `src/extension/` | The WXT shell — `srcDir` points here. Entrypoints, background, Svelte pages, runtime wiring. |
| `src/userscripts/` | 62 standalone userscript builds that reuse the feature classes. |
| `docs/` | Astro + Starlight documentation site. |
| `tools/` | Bun maintenance scripts. |

Path aliases are declared in [wxt.config.ts](wxt.config.ts) and must be used instead of deep relative imports:

`@common` → `src/common` · `@features` → `src/common/features` · `@extension` → `src/extension` ·
`@public` → `src/extension/public` · `@svelte` → `src/extension/svelte` · `@vendor` → `src/extension/utils/vendor` ·
`@userscripts` → `src/userscripts`

## Code style

Formatting is handled by Oxfmt ([.oxfmtrc.json](.oxfmtrc.json)); linting by Oxlint ([.oxlintrc.json](.oxlintrc.json)).

- Tabs, width 4. Print width 160. Double-quoted strings. Semicolons. Spaces around operators and after commas.
- `camelCase` identifiers; `UPPERCASE` for global constants.
- All code is TypeScript. Prefer `import type` for type-only imports (lint warns otherwise).
- HTML written as strings inside `.ts` files is **not** auto-formatted — format it by hand.
- Build targets are `chrome109`, `firefox128` and `edge109`; modern syntax such as optional chaining is fine and the
  linter actively encourages it.

Two lint rules catch out agents in particular:

- `document.querySelector`, `querySelectorAll`, `getElementById` and `getElementsByTagName` are **banned**. Use
  `findElement` / `findAllElements` from `@common/utils/functions/find-elements`.
- Side-effect imports are only allowed for `*.css` and `drag-drop-touch`.

## Do not hand-edit

| Path | Instead |
| --- | --- |
| `src/extension/utils/static-data/static-items.ts` | `bun run static-items` (prompts for an API key) |
| `src/extension/svelte/components/ui/**` | Vendored shadcn-svelte; add components with the shadcn CLI |
| `.wxt/`, `.output/` | Generated by WXT |
| `bun.lock` | `bun install` |

## Required for every change

1. **Changelog.** Add a line to the *first* entry of [src/extension/assets/changelog.json](src/extension/assets/changelog.json)
   — that entry is the unreleased one. Pick the right section (`features`, `fixes`, `changes`, `removed`, `technical`)
   and set `contributor` to a name that exists in [src/common/utils/team.ts](src/common/utils/team.ts). A first-time
   contributor must be added to `TEAM` with a colour no one else uses.
2. **Userscript versions.** If you changed a feature under `src/common/features/X/` and a matching
   `src/userscripts/entries/X/` exists, bump `version` in that entry's `metadata.ts`. This is what publishes the
   userscript, so skipping it silently ships nothing.
3. **Documentation.** Any feature you add or meaningfully change needs its page under
   `docs/src/content/docs/features/` created or updated. See [.cursor/rules/torntools-docs.mdc](.cursor/rules/torntools-docs.mdc).
4. **`bun run verify`** passes.

## Adding or changing a feature

Features are more wired-up than they look. A new feature with one setting touches six files:

1. `src/common/features/<kebab-name>/<kebab-name>.ts` — the `Feature` subclass.
2. `src/common/utils/data/default-database.ts` — the setting's default in `DEFAULT_STORAGE`.
3. `src/extension/runtime/script-manager.ts` — features do **not** self-register; add the `registerFeature` call.
4. The matching `*Section.svelte` under `src/extension/entrypoints/options/components/preferences/` — the toggle.
5. `preference-search-data.ts` — the search index entry.
6. `src/extension/assets/changelog.json` plus the docs page.

The area rules cover each step in detail: features and registration in
[torntools-features.mdc](.cursor/rules/torntools-features.mdc), DOM work in
[torntools-torn-page-dom.mdc](.cursor/rules/torntools-torn-page-dom.mdc), settings and API access in
[torntools-data-storage-api.mdc](.cursor/rules/torntools-data-storage-api.mdc), options UI in
[torntools-svelte-ui.mdc](.cursor/rules/torntools-svelte-ui.mdc).

## Tests

Bun's test runner, with tests co-located next to their source as `*.test.ts` (`bunfig.toml` sets the root to `src`).

```ts
import { describe, expect, it } from "bun:test";
```

Coverage is concentrated on pure helpers — formatting, Torn URL parsing, the API fetcher, the cache. There is no DOM or
browser-API test harness, so add tests when you write logic that can be exercised without a page, and don't scaffold
one for DOM-heavy feature code.

## Commits

Conventional commits, lowercase type, one logical change per commit: `feat:`, `fix:`, `chore:` dominate the history.
Reference GitHub issues in the body where relevant.

```
feat: elimination filter
fix: custom events across cross-world contexts no longer worked on Firefox
chore: bump dependencies
```
